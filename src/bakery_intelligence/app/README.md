# Interactive Evidence Demo (M2-05A)

Read-only Streamlit interface over the validated M2-04 reconstruction
artifacts. It inspects evidence; it never modifies source data, calls
paid APIs, or regenerates outputs.

## Prerequisites

- Repository checked out with the validated `main` history.
- Local reconstruction artifacts under
  `data/processed/experiment_008/reconstruction/v01_full/`
  (gitignored; generated by the M2-04 pipeline, not shipped).
- Optional: `data/raw/epic_kitchens/P04_104.MP4` enables in-app video
  playback. The evidence tables work without it.

## Install and launch

From the repository root:

```powershell
uv sync
uv run streamlit run src/bakery_intelligence/app/demo.py
```

Then open the local URL printed by Streamlit (typically
`http://localhost:8501`) in a browser.

## What the demo shows

The **Video Explorer** is the central workspace: a two-column layout
pairs the video player with a contextual evidence card. Selecting a
timestamp chip updates playback and the evidence card together, so the
selected observation, readings, provenance, units, and nearby events
are visible without switching views.

- **Video Explorer**: source video when present, the selected event
  window (142-153 s for `v01_full`), per-timestamp playback offsets,
  nearby action events, and the contextual evidence card.
- **Measurement Evidence**: original first-pass readings beside
  preferred values, verification provenance, display deltas, and unit
  provenance. First-pass/second-pass disagreements (for example the
  `"5 15"` reading at 150 s verified as `515`) are flagged. Deltas are
  display differences, never confirmed ingredient quantities.
- **Temporal Events**: weighing event with unresolved net quantity,
  plus action events with evidence references and ambiguous status.
- **Recipe Draft**: the canonical draft with `pending_review` status,
  its evidence-backed step, and explicit unresolved questions.

Navigation preserves the selected timestamp across all views through
shared session state (`navigation.py`, covered by
`tests/test_demo_navigation.py`). The sidebar radio widget is the
single owner of the active view; contextual actions ("View measurement
details", "Inspect event", back buttons) navigate through button
callbacks so sidebar and contextual navigation stay consistent.

Video seeking alternates the player between two placeholder slots on
every chip click (`video_slot_index`, covered by
`tests/test_demo_navigation.py`), because `st.video` accepts no `key`
and updated `start_time` values do not reliably reseek a mounted
player. Each click therefore mounts a fresh element at the requested
offset, including repeated clicks on the same timestamp. The UI labels
the selection as the *requested* playback position: once playing, the
browser keeps its own playback position until the next chip click.
Remount behavior is verified in a live browser session, not by unit
tests. The visual system uses a warm,
light-first bakery palette (cream, oat, caramel, espresso, sage) with
explicit text labels for observed, second-pass model, derived, and
human-assigned information; status is never conveyed by color alone.

Human-assigned units (for example `g` from the append-only sidecar)
are always labeled with `human_assigned` provenance and are never
presented as visually observed.

## Integrity guarantees

- All artifact access is read-only; adapters use `path.read_text` only.
- Missing or corrupt artifacts produce visible warnings, not crashes.
- No network access, inference calls, background jobs, or databases.
- Human correction and regeneration workflows are out of scope for
  M2-05A (planned for M2-05B/M2-05C).

## Tests

Adapter behavior is covered offline by `tests/test_demo_adapters.py`
using synthetic fixtures. The Streamlit UI itself requires a browser
session and is validated manually.
